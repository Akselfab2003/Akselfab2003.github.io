The problemContext

Companies talk to their customers through several channels at once, and the knowledge from solved cases stays buried in old threads. The goal was a single platform that integrates email, direct messages in the application and an embedded chatbot — and puts the answers to earlier problems to work.

My roleArchitect & PM

As solution architect I designed how the system fit together: a microservice backend, a UI built partly in Blazor, and real-time updates over SignalR. To keep the frontend and backend in sync, I generated a strongly typed SDK for each service with Kiota, so the UI talks to the API through typed HTTP clients instead of hand-written calls.

As project manager I ran planning in GitHub Projects. Every pull request went through code review, and CI in GitHub Actions ran the tests.

What I builtAI features

I was responsible for the embedded chatbot and the AI autocomplete. The autocomplete is a retrieval-augmented (RAG) pipeline:

  • An LLM extracts the meaning of an incoming message, which is stored as a vector embedding.
  • The embedding is used to find the most relevant earlier cases that were already solved.
  • Those solutions are passed to the LLM as the basis for a suggested answer.

The result: the system learns from previous messages and suggests responses based on how similar issues were solved before.

Where does the data go?

That's the first question for any AI feature built on customer messages. The model ran self-hosted through Ollama — on our own infrastructure rather than a third-party API.

Typed, generated SDKs also remove a whole class of mismatches between frontend and backend before they reach production.
